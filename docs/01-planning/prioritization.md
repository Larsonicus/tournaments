# Приоритизация и состав релиза

## Цель

Расставить приоритеты историй по WSJF, определить ёмкость команды на MVP и выбрать состав релиза как задачу о рюкзаке.

## Исходные данные

- Оценки SP из [estimates.md](estimates.md), компоненты WSJF, зависимости и обязательность — [data/backlog.csv](data/backlog.csv) в формате `release_planner.py` (value = CoD, effort = SP).
- Технические задачи — [data/tech.csv](data/tech.csv).
- График курса: разработка MVP идёт в ЛР 2 и ЛР 3, недели 6–12, то есть 7 недель. Старт — 19.10.2026, защита ЛР 3 — в конце 7-й недели, 04.12.2026.

## WSJF

WSJF = Cost of Delay / Job Size, где Cost of Delay = ценность для пользователя (BV) + срочность (TC) + снижение риска (RR). Все три компоненты — по шкале Фибоначчи 1, 2, 3, 5, 8, 13, 20, размер — в SP.

Как ставились оценки:

- **BV**: 20 — без истории продукт не решает основную проблему (генерация сетки); 13 — ключевой шаг сценария организатора; 8 — заметное удобство; 2–3 — улучшение для части пользователей.
- **TC**: высокая у историй, от которых зависят другие (US-01, US-02, US-09), и у тех, что нужны для демонстрации на защите ЛР 2 (истории 1–3 по плану курса).
- **RR**: высокая у историй с технической неопределённостью (US-09 — алгоритм посева и транзакции; US-10 — валидация) и у тех, что проверяют архитектуру сквозь все слои (US-01, US-04, US-07).

## Ёмкость команды

| Параметр                     | Значение                       |
| ---------------------------- | ------------------------------ |
| Число недель                 | 7                              |
| Участников                   | 2                              |
| Доступные часы на человека   | 10 ч в неделю                  |
| Коэффициент фокуса           | 0,6                            |
| Сфокусированные часы         | 7 × 2 × 10 × 0,6 = 84 ч        |
| Пересчёт в SP                | 1 SP ≈ 1,25 ч по эталону US-08 |
| Ёмкость                      | 84 / 1,25 ≈ 67 SP              |
| Технические задачи T-01…T-08 | 19 SP                          |
| **Ёмкость на истории, C**    | **67 − 19 = 48 SP**            |

Коэффициент фокуса 0,6 учитывает учёбу по другим дисциплинам, ревью, синхронизации и подготовку отчётов по ЛР. Технические задачи обязательны по заданиям ЛР 2 и ЛР 3, поэтому их SP вычитаются из ёмкости до выбора историй.

## Модель задачи о рюкзаке

Переменные: xᵢ ∈ {0, 1} — входит ли история i в релиз.

- **Целевая функция**: max Σ CoDᵢ · xᵢ — максимизируем суммарную стоимость задержки, которую снимает релиз.
- **Ограничение ёмкости**: Σ SPᵢ · xᵢ ≤ C.
- **Зависимости**: xᵢ ≤ xⱼ для каждой пары «i зависит от j» из `data/backlog.csv`.
- **Обязательные истории**: xᵢ = 1 для минимального сквозного сценария — US-01, US-02, US-03, US-04, US-07, US-09, US-10, US-11, US-12 (34 SP).

## Решение

Решение — скриптом курса `scripts/release_planner.py`: точный метод ветвей и границ и для сравнения жадный выбор по v/w (аналог WSJF). Жадный алгоритм скрипта сначала берёт обязательные истории с их зависимостями, затем по убыванию v/w добавляет историю вместе со всеми её зависимостями, если они помещаются в остаток ёмкости. Полный вывод — в [output/](output/).

```bash
cd scripts
python release_planner.py ../docs/01-planning/data/backlog.csv --capacity 48
python release_planner.py ../docs/01-planning/data/backlog.csv --capacity 34
```

| Сценарий      | C, SP | Не вошли                                              | SP  | Σ CoD | Жадное = оптимум |
| ------------- | ----- | ----------------------------------------------------- | --- | ----- | ---------------- |
| Базовый       | 48    | US-16…US-20                                           | 47  | 296   | да               |
| Ёмкость −20 % | 34    | US-05, US-06, US-08, US-13…US-20 (все необязательные) | 34  | 231   | да               |

Ёмкость −20 %: 67 × 0,8 ≈ 53 SP, минус 19 SP технических задач — 34 SP на истории. Обязательные истории занимают ровно 34 SP, поэтому выбирать не из чего.

## Сравнение решений

В обоих расчётных сценариях жадное решение совпало с оптимальным: при C = 48 ёмкости хватает на всё, кроме историй с самым низким WSJF, а при C = 34 остаются только обязательные. Чтобы понять, когда WSJF ошибается, ёмкость перебрана от 34 до 48 SP:

| C, SP | Жадное, Σ CoD | Оптимум, Σ CoD | Только в жадном | Только в оптимуме |
| ----- | ------------- | -------------- | --------------- | ----------------- |
| 38    | 252 (37 SP)   | 255 (38 SP)    | US-08           | US-05             |
| 41    | 266 (40 SP)   | 269 (41 SP)    | US-08           | US-05             |
| 43    | 275 (42 SP)   | 279 (43 SP)    | US-05           | US-13             |
| 46    | 288 (45 SP)   | 290 (46 SP)    | US-08           | US-15             |

При остальных значениях C решения совпадают.

Механизм расхождения один и тот же: жадный алгоритм берёт мелкую историю с высоким v/w (US-08, 1 SP, WSJF 6,0), после чего на более ценную историю того же порядка (US-05 или US-15, 2 SP) не хватает 1 SP, и этот 1 SP остаётся неиспользованным. Точное решение жертвует историей с лучшим отношением ценности к размеру, но заполняет ёмкость целиком. Потери небольшие (0,7–1,5 %), потому что истории мелкие относительно ёмкости; чем крупнее истории по сравнению с C, тем сильнее WSJF может ошибаться.

## Выводы

- Состав MVP: US-01–US-15, 47 SP из 48. US-16 — первый кандидат, если останется ёмкость или ускорится поток.
- При сокращении ёмкости на 20 % в релизе остаются только обязательные истории; первыми уходят список турниров, отмена регистрации, ввод счёта из сетки и рейтинг с лидербордом.
- WSJF задаёт порядок работы внутри релиза. Для выбора состава он почти оптимален только потому, что истории мелкие; при ёмкости 38, 41, 43 и 46 SP точное решение лучше на 0,7–1,5 %.
