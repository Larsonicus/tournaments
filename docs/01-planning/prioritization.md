# Приоритизация и состав релиза

## Цель

Расставить приоритеты историй по WSJF, определить ёмкость команды на MVP и выбрать состав релиза как задачу о рюкзаке.

## Исходные данные

- Оценки SP из [estimates.md](estimates.md), зависимости и обязательность — [data/backlog.csv](data/backlog.csv).
- Технические задачи — [data/tech.csv](data/tech.csv).
- График курса: разработка MVP идёт в ЛР 2 и ЛР 3, недели 6–12, то есть 7 недель. Принято: старт 02.11.2026, защита ЛР 3 — 18.12.2026.

## WSJF

WSJF = Cost of Delay / Job Size, где Cost of Delay = ценность для пользователя (BV) + срочность (TC) + снижение риска (RR). Все три компоненты — по шкале Фибоначчи 1, 2, 3, 5, 8, 13, 20, размер — в SP.

Как ставились оценки:

- **BV**: 20 — без истории продукт не решает основную проблему (генерация сетки); 13 — ключевой шаг сценария организатора; 8 — заметное удобство; 2–3 — улучшение для части пользователей.
- **TC**: высокая у историй, от которых зависят другие (US-01, US-02, US-09), и у тех, что нужны для демонстрации на защите ЛР 2 (истории 1–3 по плану курса).
- **RR**: высокая у историй с технической неопределённостью (US-09 — алгоритм посева и транзакции; US-10 — валидация) и у тех, что проверяют архитектуру сквозь все слои (US-01, US-04, US-07).

## Ёмкость команды

| Параметр                     | Значение                       |
| ---------------------------- | ------------------------------ |
| Число недель                 | 7                              |
| Участников                   | 2                              |
| Доступные часы на человека   | 10 ч в неделю                  |
| Коэффициент фокуса           | 0,6                            |
| Сфокусированные часы         | 7 × 2 × 10 × 0,6 = 84 ч        |
| Пересчёт в SP                | 1 SP ≈ 1,25 ч по эталону US-08 |
| Ёмкость                      | 84 / 1,25 ≈ 67 SP              |
| Технические задачи T-01…T-08 | 19 SP                          |
| **Ёмкость на истории, C**    | **67 − 19 = 48 SP**            |

Коэффициент фокуса 0,6 учитывает учёбу по другим дисциплинам, ревью, синхронизации и подготовку отчётов по ЛР. Технические задачи обязательны по заданиям ЛР 2 и ЛР 3, поэтому их SP вычитаются из ёмкости до выбора историй.

## Модель задачи о рюкзаке

Переменные: xᵢ ∈ {0, 1} — входит ли история i в релиз.

- **Целевая функция**: max Σ CoDᵢ · xᵢ — максимизируем суммарную стоимость задержки, которую снимает релиз.
- **Ограничение ёмкости**: Σ SPᵢ · xᵢ ≤ C.
- **Зависимости**: xᵢ ≤ xⱼ для каждой пары «i зависит от j» из `data/backlog.csv`.
- **Обязательные истории**: xᵢ = 1 для минимального сквозного сценария — US-01, US-02, US-03, US-04, US-07, US-09, US-10, US-11, US-12 (34 SP).

## Решение

Задача решается полным перебором необязательных историй (2¹¹ вариантов) с проверкой ограничений. Расчёт будет перезапущен скриптом курса `release_planner.py` на тех же CSV.

| Сценарий      | C, SP | Метод       | Не вошли                                | SP  | Σ CoD |
| ------------- | ----- | ----------- | --------------------------------------- | --- | ----- |
| Базовый       | 48    | Рюкзак      | US-16, US-17, US-18, US-19, US-20       | 47  | 296   |
| Базовый       | 48    | Жадный WSJF | US-16, US-17, US-18, US-19, US-20       | 47  | 296   |
| Ёмкость −20 % | 34    | Рюкзак      | все необязательные                      | 34  | 231   |
| Ёмкость −20 % | 34    | Жадный WSJF | US-12, US-13, US-14, US-15, US-16…US-20 | 34  | 238   |

Ёмкость −20 %: 67 × 0,8 ≈ 53 SP, минус 19 SP технических задач — 34 SP на истории.

Жадный алгоритм: истории сортируются по убыванию WSJF, на каждом шаге берётся первая история, которая помещается в остаток ёмкости и у которой выполнены все зависимости. Без повторных проходов жадный алгоритм выбирает только US-01: у US-02 с максимальным WSJF не выполнена зависимость, и дальше по списку то же самое.

## Сравнение решений

- **В базовом сценарии** решения совпадают: ёмкости хватает почти на всё, «режет» только US-16 на 8 SP с низким WSJF, и оба метода её отбрасывают. Свободным остаётся 1 SP, в который не помещается ни одна из оставшихся историй.
- **При сокращении ёмкости** жадный алгоритм набирает больше CoD (238 против 231), но решение недопустимо: он выбрасывает обязательную US-12 «Просмотр сетки» (WSJF 4,60) и берёт вместо неё мелкие US-05, US-06, US-08 с высоким WSJF. Без просмотра сетки игрок не видит результат — сценарий из видения не выполняется.
- Разница в том, что WSJF — локальная оценка «ценность на единицу работы», а рюкзак учитывает ограничения целиком: обязательность и то, что крупная история может открыть доступ к ценности других.

## Выводы

- Состав MVP: US-01–US-15, 47 SP из 48. US-16 — первый кандидат, если останется ёмкость или ускорится поток.
- При сокращении ёмкости на 20 % в релизе остаются только обязательные истории; первыми уходят список турниров, отмена регистрации, ввод счёта из сетки и рейтинг с лидербордом.
- WSJF подходит для порядка работы внутри релиза, а для выбора состава нужна модель с ограничениями.
