# Рабочее соглашение команды

**Команда:** Участник А — @Larsonicus, Участник Б — Иван **Проект:** Tournaments — сервис турниров по олимпийской системе

## Цель

Зафиксировать правила совместной работы, чтобы спорные ситуации решались по договорённости, а не каждый раз заново.

## Исходные данные

Команда из двух человек, работа частично асинхронная, процесс — Kanban ([process.md](process.md)). Документ составлен по шаблону `templates/docs/team-agreement.md` из материалов курса.

## Ритм и синхронизация

- Синхронизация: вторник и пятница в 20:00, 15 минут, созвон в Telegram — что сделано, что дальше, что мешает.
- Пополнение колонки «Готово к работе» — на пятничном созвоне, порядок по WSJF с учётом зависимостей.
- Ретроспектива — в последнюю неделю каждой ЛР, 30 минут, итоги в `docs/04-metrics/`.
- Канал связи: Telegram-чат команды; срочное — звонок.
- Время ответа на сообщение: не позже 4 ч в рабочие дни с 10:00 до 22:00.
- Требования и критерии приёмки уточняются в комментариях задачи Jira, код — в комментариях PR. Договорённости из чата переносятся в задачу или документ: чат не источник правды.

## Работа с задачами

- Методология: Kanban без итераций, пополнение бэклога раз в неделю ([process.md](process.md)).
- WIP-лимиты: «В работе» ≤ 2, «Ревью» ≤ 1, «Готово к работе» ≤ 5.
- Задача двигается по доске в момент фактической смены состояния.
- Пока в «Ревью» есть PR партнёра, новая задача не берётся: сначала ревью.
- Definition of Ready и Definition of Done — в [process.md](process.md).

## Код и ревью

- Стратегия ветвления: GitHub Flow — короткоживущие ветки от `main` вида `<type>/<ключ задачи>-<slug>`, conventional commits, слияние только через PR. Прямые коммиты в `main` запрещены.
- Размер PR: одна задача, не более 300 строк диффа; ревью начинается в течение 24 ч после открытия PR.
- Ревьюер проверяет критерии приёмки, тесты на новую логику и читаемость; то, что ловит линтер, в ревью не пишется.
- Комментарий с префиксом `nit:` необязателен, остальные закрываются до мержа. Мержит автор после одобрения и зелёного CI.
- Разногласия на ревью решаем так:
  1. каждый за 5 минут излагает свой вариант с аргументами;
  2. если вопрос решается данными — делаем замер или прототип, ограниченный 1 часом;
  3. если нет — решает ответственный за область по таблице ниже, решение записывается в PR;
  4. если вопрос касается требований курса — уточняем у преподавателя.
