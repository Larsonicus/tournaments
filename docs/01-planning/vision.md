# Видение продукта

## Цель

Зафиксировать, для кого и зачем делается турнирный сервис, как поймём, что он успешен, и что в него сознательно не входит.

## Исходные данные

Тема команды по согласованию с преподавателем: сервис проведения турниров по олимпийской системе. Объём MVP для команды из двух человек — 6–10 пользовательских историй верхнего уровня.

## Продукт в одном предложении

Для организаторов небольших любительских турниров (киберспорт, настольный теннис, шахматы в клубе), которые ведут сетку в таблицах и мессенджерах, сервис Tournaments — это веб-приложение, которое принимает регистрации, само строит сетку single elimination и продвигает победителей по введённому счёту. В отличие от таблиц, сетка не ломается при ошибке в ячейке, а рейтинг игроков пересчитывается автоматически.

## Целевые пользователи

| Роль        | Кто это                                                      | Что ему нужно                                                       |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------------- |
| Организатор | Капитан клуба, староста, модератор сообщества на 8–64 игрока | Быстро создать турнир, закрыть регистрацию, вести счёт без ошибок   |
| Игрок       | Участник любительских турниров                               | Записаться в один клик, видеть сетку и свой следующий матч, рейтинг |

## Проблема

- Сетку рисуют вручную: при нечётном числе участников путаются с bye, сильнейшие встречаются в первом круге.
- Результаты передаются в чат, организатор вручную переносит победителя, ошибки всплывают поздно.
- Нет общей истории и рейтинга: посев каждого нового турнира делается «на глаз».

## Ключевые сценарии

1. Организатор создаёт турнир: название, дисциплина, лимит участников 2–64, дедлайн регистрации, формат матча Bo1/Bo3/Bo5.
2. Игрок регистрируется на турнир до дедлайна и при необходимости отменяет регистрацию.
3. Организатор стартует турнир — сервис закрывает регистрацию и строит сетку с посевом по рейтингу и bye.
4. Организатор вводит итоговый счёт матча — сервис проверяет его по формату, продвигает победителя, после финала завершает турнир.
5. Все видят сетку и лидерборд по рейтингу Elo.

## Критерии успеха

| Показатель                                                       | Целевое значение | Как измеряем                                |
| ---------------------------------------------------------------- | ---------------- | ------------------------------------------- |
| Время от создания турнира на 16 участников до готовой сетки      | ≤ 5 минут        | Сценарий на стенде, секундомер в демо       |
| Доля введённых результатов без ручной правки сетки               | 100 %            | Интеграционные тесты на прохождение турнира |
| Время ответа `GET /tournaments/:id/bracket` на 64 участника, p95 | ≤ 300 мс         | k6-сценарий в ЛР 3                          |

## Что не входит в продукт

- Другие форматы: double elimination, круговая и швейцарская системы.
- Счёт по отдельным играм внутри матча — хранится только итог матча.
- Платежи, призовые фонды, чат, стриминг.
- Мобильные приложения и push-уведомления.
- Интеграции с внешними платформами (Challonge, FACEIT, Telegram).

## Выводы

Продукт узкий: один формат турнира и две роли. Это позволяет уложить MVP в ёмкость команды и сосредоточиться на процессе поставки. Главный риск — корректность генерации сетки и продвижения победителя, поэтому эта логика выделяется в чистые функции с unit-тестами.
