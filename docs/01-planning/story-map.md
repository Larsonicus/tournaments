# Карта пользовательских историй

## Цель

Показать путь пользователя целиком и провести линию MVP так, чтобы выше неё получился сквозной сценарий «создал турнир → провёл → увидел результат».

## Исходные данные

Истории из [backlog.md](backlog.md), состав MVP — решение задачи о рюкзаке из [prioritization.md](prioritization.md).

## Обоснование линии MVP

- Выше линии — 15 историй на 47 SP при ёмкости 48 SP на истории. Они дают полный цикл турнира и рейтинг, без которого не работает посев.
- US-16 «Корректировка результата» важна для организатора, но стоит 8 SP при невысокой стоимости задержки и не помещается в ёмкость. Берётся первой, если останется время.
- US-17–US-20 улучшают продукт, но сценарий без них работает.

## Выводы

Каждый столбец выше линии содержит хотя бы одну историю, значит MVP — это «тонкий» сквозной срез, а не набор отдельных функций. При сокращении ёмкости на 20 % линия опускается до обязательных историй (см. [prioritization.md](prioritization.md)).
